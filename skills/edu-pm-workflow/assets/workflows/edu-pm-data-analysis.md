# PM数据分析报告工作流

本工作流协助产品经理在功能上线后，快速将原始业务数据转化为结构化、可视化的分析报告，进行漏斗诊断、异常归因，并输出下一步迭代建议。

## 适用场景
- 新功能上线首周/首月的数据复盘
- A/B 测试结果分析
- 日常核心指标监控分析

## 需求目录归属规则（落盘前必读）
> 产物按「需求名」收纳，谁先开工谁建家。本工作流既可承接已有需求（复用其 `[需求名]/`），也可作为某分析专题**独立开局**以需求名建家。
1. 报告落盘前，先查项目根目录是否已存在该需求同名文件夹 `[需求名]/`：**已存在则复用**，把报告放进它的 `数据分析/` 子目录；**不存在则以需求名新建** `[需求名]/`，再建 `数据分析/`。
2. 同一需求后续做 PRD/原型/验收等，统一复用同一个 `[需求名]/`，需求名保持完全一致。
3. 只建当前用到的子目录（这里是 `数据分析/`），不预建空文件夹。`scripts/`、`.handoff/` 等共享资源仍在项目根目录。

## 执行步骤

### Step 1: 收集原始数据
1. 接收用户提供的数据源。数据形式可以是：
   - 粘贴的 CSV/Excel 文本数据
   - 业务 BI 看板的截图（需 AI 视觉解析）
   - 用户口述的几个核心关键指标
2. 确认分析的周期（日/周/月）和核心关注点。

### Step 2: 数据结构化与诊断分析
1. **指标概览**：计算核心 KPI（渗透率、转化率、留存率、日均使用次数等），并与预期目标对比，标注升降。
2. **转化漏斗**：梳理用户核心路径流转率，定位断点。
3. **异常归因**：针对偏低或暴跌的指标，结合业务逻辑推导可能的原因（例如：功能隐藏太深、定价门槛过高、UI引导弱）。
4. **专项分析**（可选）：针对不同人群（角色/渠道/地区/机型）的交叉分析。

### Step 3: 输出优化建议 (Action Items)
- 基于数据结论，输出 3-5 条具体可落地的产品优化建议，并标记优先级（P0/P1）。

### Step 4: 生成《数据分析报告》HTML
1. 产物按需求名分文件夹：在 `{需求名称}/数据分析/` 子目录中创建 HTML 报告（该需求顶层目录不存在则先创建）。
2. 文件命名规范：`{需求名称}/数据分析/{需求名称}-数据分析.html`。
3. **UI 规范**：
   - 复用宿主品牌和明暗模式；无既定主题时采用白底、深色文字与低饱和配色，保持与其他模块报告一致。
   - **核心卡片**：顶部展示 KPI 概览，包含具体数值、涨跌幅 badge。
   - **可视化图表**：使用 ECharts 实际渲染趋势、比较、占比和留存热力图，文档小型图默认 SVG。图表数据与代码计算结果一致，原始数据和图表规范同时保留。
   - **漏斗图**：使用 ECharts funnel 显示真实步骤人数；步骤转化率与累计转化率由代码计算，明细表保留分母、口径和观察周期。
   - **图表规范**：读取项目 `.agents/references/visualization-spec.md`；未安装时读取本 Skill 的 `assets/references/visualization-spec.md`。在工作台中仅输出其协议要求的正文与图表数据，全文 HTML 按需生成。
   - **洞察模块**：用高亮卡片突出“异常流失”或“超预期”的发现。
   - **行动项**：底部清晰列出下一步迭代计划。

## 输出交付物
- 沉浸式数据分析报告 (`{需求名称}/数据分析/{需求名称}-数据分析.html`)

# 产品立项报告

核心理念：**立项 = 拿证据换资源**。老板投的人、钱、时间是稀缺资源，报告的任务是把调研材料浓缩成密度足够的证据包。证据只有三种来源：用户原话、行为数据、竞品事实。没有证据支撑的判断不要写进报告。

## 工作流程

### 第 0 步：盘点输入

向用户确认三件事，材料缺的部分列成"待补清单"写进风险节，绝不编造：

1. 材料：访谈稿 / 用户反馈 / 竞品笔记 / 业务数据，各有什么
2. 产品现状：0 到 1（从无到有做新产品，重在验证需求真伪）还是 1 到 N（已有产品迭代，重在增量）——两种报告的侧重完全不同
3. 输出去向：本地 markdown，还是飞书文档（写飞书先读 references/feishu-write.md）

### 第 1 步：挖证据（材料分析）

逐段通读调研材料，按四张证据表归档，每条证据必须带原文引用（引号标注）：

| 证据类型 | 提取什么 | 用在报告哪节 |
| --- | --- | --- |
| 用户画像 | 年龄、职业、动机、关键行为特征 | 三、目标用户 |
| 场景与卡点 | 谁在什么场景遇到什么问题、现在怎么凑合 | 三、核心场景 |
| 竞品评价 | 用户对每个竞品的人格化认知、优缺点原话 | 二、竞品分析 |
| 机会信号 | 被主动且反复提出的未满足需求；被点名的竞品失败功能 | 四、需求排序 |

挖掘要点：

- 差评和吐槽是未满足需求清单，优先深挖
- 用户对竞品的"人格化描述"（像几岁、什么性格、什么风格）是定位认知最直接的证据，逐字保留
- 区分用户"说的"和"做的"：声称的需求找行为佐证，两者落差本身就是信息
- 样本局限意识：少于 8 人的定性访谈只能产出方向假设，必须写进样本风险

### 第 2 步：定目的

回答三个问题，构成报告第一节：

- 0 到 1 还是 1 到 N
- 商业目标：赚钱（订阅/买断/广告）、赚流量（先规模后变现）、还是内部提效降本
- 定价模式：免费 / 订阅 / 按量付费 / 买断——定价决定目标用户和竞品圈子

### 第 3 步：看清对手（竞品分析）

1. 四层对手地图：直接竞品（同问题同解法）、间接竞品（同问题不同解法）、替代品（用户现在的土办法）、潜在竞品（随时可能伸手的大平台），每层找 2-3 个
2. 楼层式横向拆解表：市场层（蛋糕多大/什么阶段/谁在抢）→ 定位层（一句话定位）→ 用户层（旅程卡点）→ 功能层 → 体验与商业层。单拆一个看深度，多拆几个横着比才看得出差异化空隙
3. 下结论三问：哪类人群没被服务好？哪个场景没被覆盖？哪种方案体验更好？三者必居其一，否则就是在和对手硬拼资源
4. AI 唱反调：结论写完后站到反方攻击它（市场不存在/伪需求/差异化守不住/时机不对/成本收不回），驳不倒的才写进报告，被驳倒就回上一步修正

### 第 4 步：排出先后（需求排序）

1. Kano 分类：必备型（没有就走，有了没人夸）/ 期望型（越多越满意）/ 兴奋型（没有不抱怨，有了会传播）/ 无差异（做了没人理）/ 反向型（越多越不满）
2. 价值-成本四象限：左上（高价值低成本）进 MVP；右上（高价值高成本）拆解分期或二期立项；左下顺手做排低优先级；右下不做，但要写明理由
3. MVE 设计验证节奏：每个版本都能用（完整闭环）、能测（上线前预设假设和指标）、有反馈（数据直接回答要不要继续）；把一次性押注改成分段下注
4. MVP 范围表：每行一个需求，三列勾选——MVP 内做 / 本期不做 / 以后做。判断口径一句话："这个需求不做，核心假设还验证得成吗？"验证得成就往后放

### 第 5 步：写报告

严格按 references/report-template.md 的八节结构逐节产出。各节的表格骨架、写法要点、常见坑都在模板里，写之前先读一遍。

## 写作规则

- 结论先行：每节第一句就是该节结论，证据跟在后面
- 每个判断带证据：用户原话用引号；数据注明出处；缺数据的位置写"待补"
- 砍掉的需求必须写"为什么不做的理由"，防止评审后翻旧账
- 样本局限写进风险节：定性小样本 → 方向假设，灰度数据二次验证
- 数字要能落地：指标写清基线和通过线（如"7 留相对基线 +3pp"），资源写清人数 × 周数
- 报告结尾必须有一句话立项理由
- 定稿前用第 3 步的"唱反调"把全文自查一遍再交付

## 交付

默认输出 `<产品名>-立项报告.md` 到当前目录。用户要求写入飞书时，先读 references/feishu-write.md 再动手。

## 文档图表渲染

生成图表、矩阵、流程图或格式化表格前，阅读 [references/visualization-spec.md](references/visualization-spec.md)。数据图使用 ECharts，流程与关系图使用 Mermaid，表格使用 HTML＋CSS；复用宿主品牌主题。AI 输出声明式数据与证据，宿主负责渲染。无宿主协议时使用 `chart` JSON（`pm-chart-v1`）和 `mermaid` 围栏，并保留数据表与读图结论；不使用字符拼接图。定性矩阵用类别轴，不伪造精确数值。无数据时展示证据缺口。是否已渲染及导出能力按实际环境说明；全文 HTML 仍遵守原交付流程或宿主的按需生成规则。

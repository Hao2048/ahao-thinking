# 节点工作流 2.0

对应 PRD：../需求文档/节点工作流改造-PRD.html；交互参考 V4。

## 结构

- `apps/workbench/nodes/`：22个独立节点包、3个启动模板、可复制的代码节点示例和维护手册。
- `src/node-registry.mjs`：目录扫描、定义/资源/版本校验、错误隔离、规则哈希、执行时插件加载。
- `src/flow-graph.mjs`：节点、配置、端口、分组校验；DAG拓扑与目标节点祖先子图；缓存指纹。
- `src/node-executors.mjs`：内置输入工具、AI充分性检查、统计SOP、插件统一执行协议、来源与假设传播。
- `src/flow-service.mjs`：工作流CRUD、版本快照、串行调度、暂停补充、草稿、缓存、停止、节点助手、文件确认、按需HTML。
- `public/node-app.mjs` / `node-style.css`：V4画布、目录驱动节点库/表单、节点助手和文档查看器。
- 原模块界面保留在 `/legacy.html`，原API兼容。图表沿用ECharts SVG、Mermaid、安全SVG、历史字符图识别；总结按当前文档生成。

不新增模型SDK，沿用现有 HarnessBridge.invoke。模型Key不进入节点配置或执行快照。当前节点指令由自己的包加载，不通过旧catalog拼接其他Skill。

## 存储

保留schemaVersion 1，与既有Store兼容；项目新增workflows数组。每个工作流保存id、name、revision、graph、messages、runs、nodeEpochs。graph包括nodes/edges/groups/view；节点含id/type/name/config/x/y/color。自动保存携带revision，冲突返回明确错误。运行及等待补充时不能改结构。

每轮run冻结graph、节点定义和规则哈希，记录order、version、status及各节点output。上游失败不执行下游。目标运行仅包括当前节点及祖先。只复用依赖指纹相同且成功的结果；联网与历史引用不缓存。重启将中断的执行/流式对话标为失败，等待补充状态可恢复；原有项目和文档保留。

文件先二进制解析，临时草稿15分钟后过期；确认时校验项目/工作流/节点作用域。Excel逐工作表确认，OCR继续使用现有解析器。可选文件空输入可跳过；数据充分性由后续分析节点判断。

## API

所有接口继续要求本机Host、允许的Origin和x-aipm-token。

| API | 作用 |
|---|---|
| GET /api/nodes | 扫描节点和模板；返回有效定义及独立加载错误 |
| GET/POST /api/projects/:pid/flows | 列表/创建 |
| GET/POST /api/projects/:pid/flows/:fid | 详情含流式增量/乐观锁保存 |
| POST .../:fid/run | 整体或targetNodeId祖先执行 |
| POST .../:fid/runs/:rid/resume | 补充或allowDraft后继续 |
| POST .../:fid/runs/:rid/stop | 停止，保留已完成节点 |
| POST .../:fid/nodes/:nid/chat | 即时保存用户消息、异步流式助手与问题弹窗 |
| POST .../:fid/nodes/:nid/reset | 清空当前节点对话并失效缓存 |
| POST .../:fid/nodes/:nid/html | 对一份成功文档按需生成HTML并缓存 |
| POST /api/flow-files/parse?... | 二进制文件预览 |
| POST .../:fid/nodes/:nid/confirm-file | 确认解析材料进入节点 |
| GET .../:fid/artifacts | 本项目节点产物引用 |

## 扩展流程

按nodes/README.md新增文件夹，编辑node.json和instructions.md/execute.mjs即可；主程序自动扫描、分类、生成表单和调用统一执行器。插件运行可信本地代码，按用户明确运行才导入，不是任意代码沙箱。更换底层系统权限或模型协议需要扩展核心运行时。

## 验证与打包

单元/API测试：npm test --prefix apps/workbench。节点UI测试：node apps/workbench/tests/node-browser.mjs，使用临时数据与测试模型，不使用用户Key或项目。PRD使用产品经理工作流的validate_prd.py校验。

macOS：node apps/workbench/scripts/package-mac.mjs。应用内置节点首次复制至用户数据目录nodes，源代码目录与安装版目录分别独立。应用更新不覆盖维护者在用户节点目录中的修改。无Developer ID时继续本地签名打包，沿用项目原签名配置。

## 2.0.1 文档节点大纲

共享纯函数public/node-outline.mjs用于编辑器预览、保存校验和生成校验，忽略代码围栏内的标题。AI报告节点自动获得大纲卡片与编辑器，默认大纲仍在对应节点包内维护。每个#标题拆为一份文档；生成后比对章节标题/层级/顺序与正文，漏章或空章时一次修复请求，失败不发布不完整结果。output.documents[].outline保存各文档实际使用的大纲；旧run.graph快照可作为历史版本回退展示。缓存协议升级为outline-v1，避免直接复用未经过章节检查的旧结果。分析节点和原有模块的生成行为保留原协议。

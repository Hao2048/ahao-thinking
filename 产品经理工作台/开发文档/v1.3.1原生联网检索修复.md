# v1.3.1 原生联网检索修复

## 问题与根因

v1.3.0 将默认检索设为 none。即使已有可用 DeepSeek 连接，确认研究计划仍在联网前被 publicSearch.configured 拦截。研究取材只调用独立检索服务，没有复用 Harness 原生搜索提供方。

## 当前行为

默认使用自动检索。已有 DeepSeek Messages 连接时，直接调用随应用打包的 DeepSeekSearchProvider（@deepseek-ai/dsh-web-search-deepseek），复用该连接的 Key 与端点，使用 deepseek-v4-flash 和 web_search_20250305；不要求额外检索 Key。端点统一补齐 /v1，最大原生搜索次数 3，超时 90 秒。该辅助请求按已有 DeepSeek 账户计费。

保留 Tavily、Brave API、自建 SearXNG。用户明确选择专业服务时按其设置请求，不自动切换服务。其他模型及未配置 DeepSeek 的情况可使用公开搜索页；其可用性和结果相关度受搜索网站影响，不能视为稳定专业 API。验证页面不作为结果，不绕过验证码。

指定产品预检索、联网取材预览、确认计划后的正式研究均接入同一检索入口。正式研究只提交计划公开检索词，网页正文和来源写入本次输入快照；正文失败仍区分搜索摘要，检索失败说明实际错误。不改变工作区 Skill 隔离，也不把模型回复中的 URL 当成实际搜索结果。

## 验证

- 修复前默认/旧版未配置设置的红测试失败；修复后通过。
- 47 项单元和 API 检查通过，含实际 Harness 提供方对本地模拟服务的协议验证、Key 复用、结构化来源和缺少搜索块时明确失败。
- 研究入口浏览器回归通过：无检索 Key 时确认计划，来源进入研究快照，材料与继承保留。
- 模型/检索设置浏览器回归通过：自动模式不显示额外 Key 输入，专业服务显示配置；390px 布局无全局溢出。
- 打包桌面验收通过：v1.3.1 独立启动、真实 SDK 流式回复、问题弹窗、OCR、钥匙串加密、重启恢复。
- 已安装应用真实联网测试：公开检索词“DeepSeek Harness GitHub 开源项目”，使用原有 DeepSeek 连接返回 5 项相关来源，5 项正文成功、0 项失败。测试只生成预览，未加入项目材料，未自动运行用户的研究计划。
- 应用签名严格验证、DMG 校验通过。保留原应用备份，项目与研究计划继续可用。

## 说明

此修复针对研究/取材链路；AI 工作助手仍按既定边界澄清材料，正式研究由确认计划入口启动。联网资料用于二手研究，市场接受度仍需实际用户验证。

旧版 enhanced-browser.mjs 的综合测试仍使用已经移除的“运行当前模块”按钮，未通过该过时步骤；本次对应入口与检索、模型设置、桌面链路的专门回归已通过。

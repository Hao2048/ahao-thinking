# v1.4.1 输出截断修复与运行扫描

## 本次原因

实际失败的 Harness session 以 `turn/end: max-tokens` 结束：输出 12,001 tokens，文字回复 5,288 字符，JSON 尚未闭合。原工作台把它统一显示为“没有返回有效 JSON，请调整材料”，错误归因到用户材料。

## 改动

- 按用户要求移除工作台 SDK 调用的固定 `maxTokens: 12000`，以及兼容接口的 `defaultMaxTokens: 16000`。不再覆盖 Harness 的模型默认输出能力；模型服务的输出与上下文边界仍由服务和适配器决定。
- 三份研究文档分别生成；自定义多文档大纲也按文档执行，每份保持当前模块唯一 Skill、冻结材料及大纲。
- 读取 SDK 完成事件，区分服务输出截断与格式问题。截断时按章节递归拆分（最多两次拆分深度），合并完整 Markdown 片段；从不补括号伪造完整结果，也不把截断正文显示为完成文档。
- 无法进一步拆分时给出准确的截断说明，保留旧版本。网络、连接或格式错误不做无限重试。
- 结果展示标题增加绿色扫描动效、阶段标记及 aria-busy。显示联网、材料检查、文档序号、分段处理、HTML 生成等真实阶段；完成或失败时停止。启动后滚动到结果区，减少用户寻找运行状态的成本。
- 系统减少动态效果偏好下停止扫描，继续显示明确文字状态。
- 修复助手任务失败后的按钮：模块任务“重新运行”进入当前模块的检查/计划确认链路，普通聊天保留“重新生成”。

## 验证

原始失败日志在旧解析器中稳定复现。回归测试覆盖截断、分段合并、无法拆分的正确报错与不接受残缺 JSON。实际日志回放使用原始完成原因和截断正文，后续回复为本地测试替身，零网络请求；分段恢复得到三份完整测试文档。

57 项单元/API 检查、12 模块真实 SDK（含三份独立报告）、五项真实 SDK 协议与流式检查、工作台界面回归、扫描动效/减少动态效果/失败重跑验证通过。协议测试使用本地模拟供应商，未把原项目资料发送到真实模型。

# 产品经理工作台 · v0.1 开发方案

## 交付与基础

本地单人浏览器工作台，应用代码在 `apps/workbench`。通过本地 `deepseek-harness/packages/sdk/client` 官方 SDK 启动 `dsh --profile sdk-minimal`，以补丁挂载 Harness 的 pi-ai 模型适配器。沿用 Harness 会话、代理循环、供应商适配器与 JSONL 持久化；业务服务管理产品项目、输入和产物。独立应用层避免覆盖现有 Harness 桌面端的未提交改动。

界面沿用确认的浅色绿色三栏原型：阶段导航、模块输入与产物、AI 助手。窄屏将助手折至正文下面。首版用浏览器原生模块与 Node HTTP 服务，无额外应用运行依赖。

## 文档清单

1. 产品需求文档（HTML）：用户场景、范围、业务规则、界面交互、模型设置、流程与待确认事项。
2. 本开发方案：架构、数据结构、接口、模型桥接、开发批次。
3. 启动与使用说明：环境、启动入口、模型接入、材料示例与限制。
4. 验收清单：模块独立运行、混合输入、版本交接、数值口径、模型路由与错误处理。
5. 验证记录：实际执行命令、覆盖范围、未验证事项。

## 模块与职责

- `src/catalog.mjs`：阶段、子模块、输出要求与对应 skill 路径。
- `src/domain.mjs`：外部输入校验、结果校验、CSV 汇总漏斗确定性计算；不调用模型。
- `src/store.mjs`：本地 JSON 仓储、串行事务、临时文件替换、权限限制。
- `src/harness.mjs`：SDK 运行、连接配置补丁、超时与进程清理、skill 指令快照。
- `src/server.mjs`：本地接口、静态文件与任务调度。
- `public/`：界面、设置表单、文件读取、状态轮询与导出。

Skill 仅从 `/Users/penghao/Documents/Skills` 读取，不改 skill 源文件、不复制至已安装目录。每次运行读取主 skill 和 references 文本，记录 SHA-256；提示词区分 skill 指令与用户材料。首版材料研究不配置联网工具，研究报告必须标明外部证据缺失。输出原型 HTML 通过隔离 iframe 预览。

## 数据结构

- Project：id、name、createdAt、inputs、runs、messages。
- Input：id、moduleId、kind（manual/file/chat/artifact）、title、content、evidence（user_statement/material/test_data/ai_hypothesis）、source、createdAt。源产物引用固定到 runId + artifactId。
- ModelConnection：id、name、model、api、baseURL、apiKey、createdAt。服务端持有密钥；返回浏览器的目录只有 configured 标记。选定的连接 ID 存在 settings.activeModelId。
- Run：id、moduleId、version、status、inputSnapshot、modelSnapshot（不含密钥）、skillSnapshot（哈希与文本）、sessionId、startedAt、completedAt、result/error。
- Result：summary、structuredData、documents（id/title/format/content）、charts、openQuestions。
- Chat：用户消息与 AI 回复；AI 提议 input 经用户确认才写入输入仓库。

输入快照及产物版本不可回写。并发运行同一项目同一模块拒绝第二次请求；项目不同模块可并行。事务以服务端最新数据提交，避免运行完成时覆盖期间新增材料。运行过程中切换模型只影响下一次请求。进程重启把中断的 running 标为 failed，保留已有成功版本。

## 接口

| 方法与路径 | 行为 |
|---|---|
| GET /api/state | 项目、目录、无密钥模型配置与当前默认模型 |
| POST /api/projects | 创建项目 |
| POST /api/projects/:id/inputs | 添加输入或确认 AI 提议 |
| DELETE /api/projects/:id/inputs/:inputId | 移除输入，既有运行快照保持不变 |
| POST /api/projects/:id/inherit | 指定 run/artifact/targetModule，添加不可变交接输入 |
| POST /api/projects/:id/runs | 冻结输入及模型、返回运行 ID；后台执行 Harness |
| POST /api/projects/:id/chat | 当前模块对话，返回 reply/proposedInput |
| POST /api/models | 添加连接（支持原生 DeepSeek Messages、OpenAI Chat Completions、Anthropic Messages） |
| POST /api/models/:id | 编辑连接；留空保留密钥 |
| DELETE /api/models/:id | 移除连接；运行中的模型暂不移除 |
| POST /api/models/:id/test | 发起真实 SDK 请求验证连接 |
| POST /api/settings | 选择默认模型 |

浏览器轮询 /api/state 观察任务，无伪造 token 流。UI 导出本次运行 JSON、文档 Markdown/HTML/JSON。输入暂限 TXT/MD/JSON/CSV；文件单次和合计上限在 domain 中集中定义，拒绝空材料。漏斗 CSV 首版为汇总人数格式 `step,users`，人数必须非负整数、至少两步且单调不增；原始事件日志、同群用户去重与时间窗需要后续事件适配模块。漏斗数字由代码计算，AI 仅解释，不可覆盖。

## 模型与运行

没有密钥或没有选择模型时拒绝运行，不自动使用演示结果。内部接入连接在设置中添加，可多个供应商/模型并存。每次启动 SDK 子进程使用固定连接及私有临时 YAML 补丁，密钥只通过子进程环境引用传入。禁用 minimal 的 shell 工具，模型按要求返回 JSON 结构；SDK 会话保存完整请求，业务服务校验解析后提交产物。超时关闭 Harness 并等待进程退出；不完整 JSON、无文档、错误结果均标为失败。

本地服务仅绑定 127.0.0.1，接口验证 Host/Origin 并要求本次启动随机 token。静态目录不能访问 data 或任意磁盘文件。密钥保存在本地权限 0600 的 settings JSON（首版尚未接系统钥匙串）；仅适合个人本机使用。输出文本用转义渲染；HTML 原型在无同源权限的 iframe 中显示，限制网络连接。

## 开发与验证批次

1. 先落 PRD、开发方案、流程与验收清单。
2. 完成项目、输入、产物、版本和交接业务服务。
3. 接 Harness SDK、模型设置与真实连接测试。
4. 实现六阶段与助手界面，支持独立模块入口和导出。
5. 使用本地模拟模型 API 运行真实 Harness composition，验证模型路由及会话日志；再做浏览器操作与截图。没有真实供应商密钥时，不能宣称真实供应商端到端验证完成。

后续：联网证据检索、二进制文件解析、原始事件漏斗/留存、团队协作、系统钥匙串、Electron 分发。均不混入本期已完成清单。

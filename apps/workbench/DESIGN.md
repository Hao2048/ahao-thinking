# C 方案 · v2.3.0

用户已选定 C 方案，并要求增加银白主题，补齐左侧项目选择和工作流列表，修复右侧错位。

## 维护位置
- 布局/状态基础：public/node-style.css
- 深色/银白语义主题与 C 布局：public/node-themes.css
- 节点分类色与自定义底色对比：public/node-palette.mjs
- 主题偏好：settings.appearance.theme，通过 /api/appearance 校验并存储；不依赖会随本地服务端口变化的浏览器存储。

## 规则
- 两主题共用尺寸、间距、布局和功能；只替换语义色。
- 标准栏宽 104px / 弹性画布 / 310px，紧凑 100px / 弹性画布 / 280px。
- 中间标题与右侧节点标题均70px，标签栏均34px。右侧不设独立外边距或圆角，四边与工作区对齐。
- 左侧必须显示项目选择、已有工作流及新建入口；长名称最多两行并提供全文title，工作流列表内部滚动。
- 节点224×154px；窄导航、底部横向工具栏和低饱和分类色保留 C 的视觉特征。
- 来源列表的“已连接”只表示连线，不代表材料齐备或已验证。
- 文档阅读区可保留纸白底，以匹配导出内容。
- 配色、节点库、弹窗、表单、焦点、原生容器标题栏须一起适配主题。

## 已验证范围
浏览器内模拟桌面容器样式，在1520×1000、1100×760、1000×700检查两主题的边界和标签栏对齐、项目/工作流可见及切换。验证跨端口重启偏好、正常文字对比、配置保存、大纲、目录发现、对话及报告导出。紧凑窗口的“适应画布”仍是总览；阅读节点正文时可放大或平移。这不等同于本轮原生 macOS 模型全流程验收。

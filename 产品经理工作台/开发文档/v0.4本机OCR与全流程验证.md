# v0.4 本机 OCR 与全流程验证

需求：处理访谈截图、PNG/JPG、扫描 PDF 和含图片的混合 PDF。提取先预览再确认；文件来源、OCR 方法和编辑状态保留，并随任何模块交接传递。不得把 OCR 入库确认当成数据准确性已验证。

实现：native/ocr.swift 使用 Apple Vision revision 3，中英文语言和 accurate 模式；PDFKit 逐页渲染，图片使用 ImageIO 缩略图处理方向。图像最多 5000 万像素；PDF 最多 30 页，最长边渲染 2400 像素；提取文字最多 512 KB。含文字的混合 PDF 也逐页识别，识别不到时保留嵌入文字；全空结果报错，不返回伪材料。

Node 使用固定 helper 路径和固定格式参数，通过标准输入传递原始字节，不创建材料临时文件。最大 20 MB，两项解析并发，最长 120 秒，输出最多 1 MB，超限终止子进程。helper 同主机服务进程组，应用强制退出时一并终止。OCR 不接网络服务；确认文字在模块运行时仍会发送给用户所选模型。

打包先编译 helper，最低目标 macOS 13 / arm64，最终资源目录包含二进制。选择与 Swift 编译器匹配的 SDK；支持 AIPM_MACOS_SDK 覆盖，避免机器默认新 SDK 与较旧 Swift 不兼容。不修改系统 SDK、工具链或源 skill。

验证：真实中英文 PNG/JPG/纯扫描 PDF，签名伪造、损坏文件、超过 30 页限制；API 草稿确认、编辑标记；浏览器普通扫描 PDF 失败后勾选 OCR 重试、预览不入库、确认来源、390px 布局；六阶段 14 模块通过官方 Harness SDK 顺序运行、跨模块来源传递、确定性统计注入及重启恢复。模型服务为本地模拟供应商，不代表专业文档质量。

正式分发：本机只有 Apple Development 身份，没有 Developer ID Application 身份；本次仍使用本地开发签名。正式签名、公证、自动更新与 Intel 适配未完成。

依据：[Apple Vision 文档](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)、[Apple PDFKit 文档](https://developer.apple.com/documentation/pdfkit/pdfpage)。
